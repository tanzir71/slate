# Releasing Slate

The landing page and browser app ship together from the same commit. GitHub Pages serves the landing at `/slate/` and the app at `/slate/app/`; `/slate/demo/` redirects to the Sample Space.

1. Finish the release scope and run `pnpm verify`. WebKit storage tests use isolated persistent profiles and require Playwright 1.65.1 or later. Windows WebKit has additional OPFS limitations; validate the complete suite on Linux/macOS as well as supported Windows engines.

   CI enforces the unchanged Lighthouse and typing budgets on its Linux reference runner, and Pages repeats them before publication. Typing still gates Chromium, Firefox, WebKit and mobile Chromium at p95 < 16 ms in CI. Windows/macOS typing and macOS Lighthouse run as diagnostics with failed evidence uploaded; their native builds and supported-browser functional tests remain required. The platform workaround runs `pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm build:site && pnpm perf && pnpm e2e:desktop && pnpm e2e` on macOS, with timing budgets checked separately on Linux. Windows uses its supported engine arguments. [Performance reference and measured limits](docs/performance-testing.md) explains this assumption for the handover's unspecified benchmark hardware; `pnpm verify` retains its strict local checks.
2. Update workspace package/app versions, Rust manifests/lockfiles, `CHANGELOG.md`, and `apps/web/public/whats-new.json`. The site build rejects disagreement between the root version, app version, release notes and a release tag. The web version label is injected from its package metadata. Update the landing copy only for features that now work, and refresh `docs/compare-sources.md` and the dated comparison footnote.
3. Run `pnpm build:site` and `pnpm perf:site`. The build renders shared Lucide icons locally, captures the **real Sample Space** using `pnpm shots`, and assembles and verifies `site-dist/`. Fonts, brand assets and scripts are local. The site checks enforce a 10 KB landing-JS budget and a 250 KB gzip app-shell budget. Lighthouse enforces the landing's score, loading and layout budgets. Marketing font subsets are committed; to regenerate them, install `fonttools[woff]==4.63.0` and run `python scripts/subset-landing-fonts.py`.
4. Commit the source and generated marketing assets, push the commit to `main`, then push the matching `vX.Y.Z` tag.
5. The **Deploy Slate website and app** workflow resolves one immutable commit. From v0.3 it first builds unsigned Windows x64 NSIS, Linux x64 AppImage and universal macOS ZIP previews. It then installs browser engines, rebuilds the site and screenshots, compares the pinned visual baselines, runs Chromium/Firefox/WebKit functional tests and the separate `pnpm perf:typing` gate under `/slate/`, publishes the single Pages artifact, and checks the live landing-to-editor save/reopen flow. It verifies each desktop artifact's version, commit, size and checksum before attaching all three downloads plus manifests/checksums to a draft GitHub Release and publishing it. Notes come from `RELEASE_NOTES_vX.Y.Z.md` when present and generated notes otherwise. Failed builds/checks prevent publication. Older v0.2 releases remain browser-only.

   `pnpm build:desktop-preview` builds the current host's unsigned package locally. [Desktop preview details](docs/desktop-preview.md) cover prerequisites, downloads and current native limitations. The dedicated packaging workflow also runs when its source/config changes, so its three-platform result can be reviewed before tagging. The landing's secondary CTA changes to the matching release's **Desktop preview** link only from v0.3; its primary browser CTA stays available.

Publishing a release in GitHub also deploys that release's tag. For an initial landing update or a deliberate redeploy, run the workflow manually against the desired ref. GitHub Pages uses **GitHub Actions** as its build source; the `github-pages` environment permits branch `main` and tags matching `v*`. Preserve both policies so release tags are allowed to deploy.

Do not use Figma exports as product screenshots or advertise unshipped blocks, templates, Tidy, automation or Sync. Re-run `pnpm shots` after app changes. It captures the real Light and Dark workspace plus matching responsive mobile captures; the landing `<picture>` and conditional preloads follow the viewer's system theme without changing image dimensions or fetching both variants.
